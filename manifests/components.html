# Usage

## Overview

An accordion condenses long content into scannable headers. Users reveal one or more panels on demand — which also means content stays hidden until they open it.

### Variants

<Canvas of={AccordionStories.SingleExpand} />

<Canvas of={AccordionStories.MultipleExpand} />

<Canvas of={AccordionStories.Styles} />

Single- vs multiple-expand is behavior (`expandMode`), not a Figma variant. Bordered and Borderless are the Style variant.

### When to use

- To condense long content into scannable headers that users open on demand.
- For FAQ-style content, where users pick the questions they need.

### When not to use

- For primary navigation.
- For content users must read in full.

## Formatting

### Anatomy

1. **Header** — a heading element wrapping the trigger button; the whole row is the hit target.
2. **Title** — start-aligned label for the section.
3. **Icon** — chevron showing collapsed or expanded; decorative.
4. **Content panel** — revealed on expand.

### Alignment

The title is start-aligned and the icon end-aligned on the same row. The trigger spans the full header width.

### Placement

Items stack vertically at full width — never side by side. Spacing between items is consistent; borderless accordions rely on it as their only separator. Avoid nesting accordions; if you must, indent and limit to one level.

<Canvas of={AccordionStories.DoDont} />

## Content

- **Title** — wrapped in a heading (h2–h4) that fits the page outline.
- **Panel content** — every collapsed panel shows its icon, so hidden content always has a visible cue.

## Behaviors

### States

Items start collapsed (Default). Activating the trigger toggles its own panel; in single-expand mode, opening a panel collapses the one that was open.

- **Default** — collapsed, resting.
- **Hover** — the header background shifts (`surface/bg/subtle`).
- **Focused** — 3px focus ring on the header; never suppressed.
- **Expanded** — panel visible, chevron rotated 180°.
- **Disabled** — dimmed, can't change state, skipped in tab order.

<Canvas of={AccordionStories.Disabled} />

### Interactions

**Mouse** — clicking anywhere in the header toggles the panel.

**Motion** — panels animate height and opacity (about 200ms, ease-out) and the chevron rotates 0° → 180° in sync. With prefers-reduced-motion, toggling is instant.

# Accessibility

## What the design system provides

- A Focused state with a 3px ring on the header, on both styles.
- A chevron on every item, so collapsed panels always have a visible cue.
- A Disabled state for triggers that can't change.
- A full-width header, so the whole row is the hit target.

## Development considerations

- Wrap each trigger `<button>` in a heading (h2–h4). Never place the button outside the heading.
- Set `aria-expanded` on the trigger and `aria-controls` pointing to its panel.
- Give the panel `role="region"` and `aria-labelledby` pointing to the trigger; use the `hidden` attribute when collapsed.
- Mark the chevron `aria-hidden="true"`.
- Disabled triggers use `disabled` and are skipped in tab order.
- Respect prefers-reduced-motion — remove height and rotation animation.

## Overview

Avatars represent people and entities at a glance. Use AvatarGlyph on its own, or AvatarIdentity to pair it with a name, email and optional trailing icon.

<Canvas of={AvatarStories.ContentTypes} />

### When to use

- To represent a person with their photo or initials.
- To represent a system account, bot or non-person entity — Icon type.
- To identify someone next to their name and email — AvatarIdentity.

## Formatting

### Anatomy

1. **Avatar** — an AvatarGlyph (image, icon or initials).
2. **Name** — the person's or entity's name.
3. **Email** (optional) — secondary line.
4. **Trailing icon** (optional) — e.g. a chevron for a menu.

<Canvas of={AvatarStories.Identity} />

### Sizes and colors

Derive an initials avatar's color from a hash of the user's name or ID, so the same person always gets the same color.

<Canvas of={AvatarStories.ColorsAndSizes} />

<Canvas of={AvatarStories.DoDont} />

## Content

**Initials**

- First letter of the first and last name — Jane Doe → JD.
- If the initials don't fit, shrink the font to fit rather than clip.

**Image**

- Needs alt text that names the person.
- If the image fails to load, fall back to the icon (if configured), then to initials.

## Behaviors

### States

AvatarGlyph is static. AvatarIdentity has interactive states for when it opens a profile card or menu: Default, Hover (`surface/bg/subtle`), Focused (3px focus ring), Active (pressed), Selected (persistent highlight), Disabled.

### Interactions

An avatar that opens a profile card or menu needs hover and focus states like a button. A purely decorative avatar has no hover styling, so it doesn't look clickable.

### Variants

- To give quick, one-click navigation back to parent levels.

### When not to use

- As the primary navigation of the app.

## Formatting

### Anatomy

1. **Item (link)** — a clickable ancestor level.
2. **Separator** — a decorative divider between items (chevron or slash).
3. **Collapse trigger** (optional) — an ellipsis that reveals hidden middle items.
4. **Current page** — the final item; the active location, not interactive.

Items and separators sit on one horizontal line, with equal spacing around each separator. Use one separator style for the whole trail.

**Item labels**

- Each item except the last names and links to its parent level.

**Current page** — the final item names the page the user is on.

**Overflow content** — When the trail has more items than maxItems, the middle items collapse behind the ellipsis trigger. The root and the current page always stay visible.

- **Link** — Default, Hover (underline), Focused (3px focus ring) and Disabled (rare: an ancestor with no valid target).

# Usage

## Overview

A button triggers an immediate action in the current context — submitting a form, confirming a choice, opening something or deleting an item. Four emphasis levels (Primary, Secondary, Ghost, Danger) keep the most important action on a screen the easiest one to find.

Use buttons for actions only. If activating it takes the user to another page or location, it is navigation and must not be a button.

### When to use

- To let users submit, confirm, open or delete something immediately.
- To mark the single most important action in a context — **Primary**.
- To offer supporting actions of lower weight next to a primary one — **Secondary** or **Ghost**.
- To trigger destructive or irreversible actions such as delete or remove — **Danger**.

### When not to use

- When the action navigates to another page or location — use a text link instead.
- Don't use Danger styling for actions that aren't destructive — use Primary, Secondary or Ghost.

## Formatting

### Anatomy

1. **Container** — the interactive wrapper; owns variant, size and state.
2. **Icon** (optional) — leading or trailing, never both. Vertically centred with the label. Decorative icons are hidden from assistive technology.
3. **Label** — text describing the action. Required unless the button is icon-only.

### Sizes

Every variant shares the same size scale. Each size defines its own height, horizontal padding, font size and icon size.

Content is always centred horizontally and vertically. The icon sits on the side set by the icon property and is vertically centred with the label; the icon–label gap is the same across variants.

Buttons hug their content within the size's padding and are not stretched.

## Content

**Label**

- Use a verb that describes the action, e.g. Save, Delete, Open.
- Required on every button unless it is icon-only.

**Icon**

- Optional — leading or trailing, never both.
- Decorative icons must be hidden from assistive technology.
- Icon-only buttons must have an accessible label (`aria-label`).

## Behaviors

### States

A button has no persistent on/off state: it runs its action and returns to rest. Every variant starts in the Default state.

- **Default** — resting.
- **Hover** — the pointer is over the button.
- **Pressed** — during a press; gives immediate visual feedback so the press registers.
- **Focused** — keyboard focus; always shows a visible focus indicator.
- **Disabled** — non-interactive, with reduced emphasis.

**Mouse** — Clicking anywhere on the button runs its action. Disabled buttons ignore clicks.

### When to use

### When not to use

- For information that isn't urgent — use an inline [Alert](?path=/docs/components-alert--docs) instead.
- For tasks users repeat often — let them complete it on the page.
- When even the largest size isn't enough room — use a full page.

## Formatting

### Anatomy

1. **Title** — a short, specific verb phrase naming the task.
2. **Subtitle** (optional) — short context for the title (Has subtitle).
3. **Close icon** — always available for dismissal.
4. **Body** — message text and/or embedded content such as form fields.
5. **Secondary action** — e.g. Cancel, on the left.
6. **Primary action** — the one action that completes the task, on the right.

### Sizes

Small · 400px, Medium · 480px, Large · 640px. Choose the size by content: brief text fits Small; complex embedded content needs Medium or Large. If content keeps scrolling, move up a size; if the largest isn't enough, use a full page.

<Canvas of={DialogStories.Sizes} />

### Placement

Center the dialog vertically for short, predictable content, or pin it at a fixed offset from the top for longer or variable content. Use a dimmed backdrop by default. Clicking the backdrop may close passive dialogs, but never transactional or destructive ones. Avoid opening a dialog from inside another dialog.

### Do and don't

- **Do** — secondary (Cancel) on the left, primary on the right — one clear emphasis. **Don't** use two primary buttons — the user can't tell which action is safe.
- **Do** — for destructive actions, name the action in the title and use a danger-styled, specific button. **Don't** use vague titles or buttons like OK for a destructive action.

## Content

- **Title** — a short, specific verb phrase that matches whatever opened the dialog. For a very short message, let the title carry it and skip the body.
- **Subtitle** — only when the purpose isn't obvious from the title.
- **Body** — brief; only the fields and content needed to complete the task.
- **Buttons** — short, specific verbs (Delete, Save, Add), not vague labels like Done. OK is fine only for the acknowledgment pattern.
- **Overflow** — when the body needs to scroll, the header and footer stay fixed and only the body scrolls. Content never scrolls horizontally — move up a size instead.
